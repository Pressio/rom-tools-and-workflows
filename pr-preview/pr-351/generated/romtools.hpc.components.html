class romtools.hpc.components.BaseTransferManager(*, files, config=None, logger=None, campaign_directory=None)[source]#

Bases: CampaignComponent

Stages the files a campaign needs into its run directory, and brings its results back afterwards.

Nothing moves by default: a dispatcher whose work already runs against the files in place needs neither half. Subclasses override whichever half genuinely has work to do.

Parameters:

  • files (BaseFileManager) – The file manager whose resolve_path decides what paths mean

  • campaign_directory (str) – The campaign directory results are gathered into

  • config (dict) – The dispatcher’s configuration dictionary

  • logger (Logger) – An instance of the Logger class for logging

Raises:

ValueError – if the configured collect or upload patterns are invalid.

class romtools.hpc.components.StagedCaller(run_cmd, *, files, config=None, logger=None)[source]#

Bases: BaseCaller

Runs the target under a separate interpreter, through a runner script staged in a scratch directory beside the run directory.

Arguments and results travel as a JSON + .npz pair, so that interpreter needs no access to romtools; run_cmd and files decide which machine it lives on.

Parameters:

  • run_cmd – Callable that issues a shell command on the execution host

  • files (BaseFileManager) – The file manager used to stage inputs and read results back

  • config (dict)

  • logger (Logger)

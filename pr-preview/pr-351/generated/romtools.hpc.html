romtools.hpc#

Tools for running ROM workflows on HPC resources.

Workflows take a dispatcher, which decides where model evaluations run: LocalDispatcher keeps them in place, RemoteDispatcher sends them to a cluster over SSH and brings the results back.

class romtools.hpc.BaseDispatcher(campaign_directory='hpctools', logger=None, config=None)[source]#

Bases: ABC

Shared configuration, logging, and public API for the dispatchers.

The public methods here are a flat facade over composed helpers, so that workflows and models depend on one stable interface rather than on how the work is split up internally. Subclasses install the local or remote implementation of each helper, and only override a method when the behavior genuinely differs.

class romtools.hpc.LocalDispatcher(campaign_directory='hpctools', logger=None, config=None)[source]#

Bases: BaseDispatcher

Runs ROM workflows on the machine this process runs on.

Paths address the local filesystem and commands run in a local bash shell rather than over SSH. That machine may itself be a cluster node, in which case submit_job() reaches the scheduler directly and results need no transferring; upload() copies the configured files into the run directory rather than sending them anywhere.

Parameters:

  • campaign_directory (str) – The directory jobs run in when given no run_directory

  • logger (Logger) – An instance of the Logger class for logging

  • config – A YAML path or a Configuration. Defaults to reading the command line.

class romtools.hpc.RemoteDispatcher(campaign_directory='hpctools', logger=None, connection=None, config=None)[source]#

Bases: BaseDispatcher

Runs ROM workflows on a remote host over SSH, connecting as user@remote:port.

Coordinates composed helpers rather than doing the work itself: files go through RemoteFileManager, Python calls through RemoteCaller, batch jobs through SlurmJobManager, and archives through RemoteTransferManager. Paths are taken relative to the configured remote root.

Parameters:

  • logger (Logger) – An instance of the Logger class for logging

  • campaign_directory (str) – An optional string naming the directory this campaign runs in, relative to the remote root. It is mirrored locally and under the remote root.

  • config – A YAML path or a Configuration. Defaults to reading the command line.

  • connection (Connection | None)

run(cmd, run_directory=None)[source]#

Run a command directly on the remote host, without SLURM.

This lands wherever the SSH session does, which on a cluster is the login node, so it suits quick staging or preprocessing; anything long or parallel belongs in submit_job(). run_directory is relative to the remote root, and defaults to the root itself.

Returns a Result object (with stdout, stderr, exit_code, ok)

Parameters:

  • run_directory (str)
